# 02 评测设计

> 本文件定义“怎么判定答对了”。**这是整个项目可信度的地基**——旧项目在这里栽了跟头（评测集与语料同源 + 同名覆盖导致结果不可复现）。

---

## 一、三条硬原则

### 原则 1：评测集与语料解耦（反同源）

**旧项目的致命缺陷**：
- A 类 60 条的金标 = 语料原文自动抽取，查询里已含法名+条号 → 判分只看文件名 → 退化成标题匹配
- D 类案例库的选取依据就是金标（`case_include.json` 先入池再补足）→ **答案键就在语料里**
- 结果：148 条里 41% 的题在测"能不能匹配到标题"，D 类的 0.32 是"在答案集里检索"

**本项目的做法**：
- 每一类题标注**同源等级**（强 / 中 / 弱），在结果说明中**主动标注**
- **强同源类只作回归基线**，不当作能力证据
- 判分口径改为**不依赖"文件命中"**：A 类加条号校验；D/E 类判"版本是否正确"，答案不是某段原文

### 原则 2：评测集冻结且版本化

**旧项目的致命缺陷**：`eval_set_v1.jsonl` 被 v1→v2→v3 就地覆盖三次，
导致 E2 实验（跑在 v2 上）与 v3 基线被并排对比，**且 E2 永远无法复现**。

**本项目的做法**：
```
eval/sets/v1.jsonl            冻结后不再修改
eval/sets/v1.manifest.json    {content_hash, n_by_class, builder_commit, created_at}
```
新版本一律新文件名（v2.jsonl），旧版本保留。**任何实验必须声明用的是哪一版。**

### 原则 3：阈值在 dev 上标定，在 test 上报告

**旧项目的缺陷**：拒答阈值 = 同一评测集内非拒答类最高分的 P5，然后**在同一集合上**报告准确率 → 泄漏。

**本项目的做法**：F 类 30 条拆成 dev(15) / test(15)；阈值在 dev 上标定，在 test 上报告。
同时报**双侧**：拒答召回 + 误拒率。

## 二、六类题

### A 法条精确（n=60，同源等级：强）

- **问法**：`《中华人民共和国劳动合同法》第三十八条的内容是什么？`
- **判分**：**文件命中 AND 条号命中**（旧项目只判文件）
  - 条号命中 = top-1 片段的 `heading_path` 含该条，或片段正文以该条号开头
- **为什么保留**：它是回归基线——底座坏了这里立刻掉。但**必须在结果中标注它是强同源**
- **已知弱点**：查询含法名+条号，接近标题匹配。**这一点要在文档里主动说明**

### B 口语化咨询（n=40，同源等级：中）

- **问法**：`试用期工资最低能给多少？`
- **判分**：期望来源集合的召回（|gold ∩ top5| / |gold|）
- **说明**：手写 + 原文 grep 校验存在性。**只保证金标存在，不保证唯一正确**——多法条可答的问题只给一个金标会判罚偏严，这是已知局限

### C 跨法条关联（n=20，同源等级：弱）

- **问法**：`合同没约定违约金，一方违约造成损失怎么赔？能调整吗？`
- **判分**：≥2 个期望来源同时进 top-5
- **注意**：n 小，一位 = 5pp，**不要报三位小数**（旧项目 n=6 报 0.125 是伪精度）

### D 版本冲突（n=40，同源等级：弱）—— **本项目核心题**

从 377 个多版本标题中抽 40 个，三档难度：

| 档 | 问法 | 正确行为 | 判分 |
|---|---|---|---|
| 简单 | 某法条的内容是什么？ | 返回 `status_code=3` 的版本 | top-1 所属文档 `status_code==3` |
| 中等 | 这条被修订过吗？有哪些版本？ | 列出全部版本 + 标注时效 | 返回的版本集合覆盖 ≥2 个，且标出哪个现行有效 |
| 困难 | 2020 年时这条怎么规定的？ | 返回 2020 年时生效的版本 | top-1 所属文档满足 `effective_date <= 2020-12-31` 且是当时最新 |

**这是唯一能证明"这不是通用 RAG"的一类题。** 答案不是"某段原文"，是"哪一版"。

### E 位阶冲突 / 未生效（n=20，同源等级：弱）—— **本项目核心题**

| 子类 | n | 问法 | 正确行为 |
|---|---|---|---|
| 未生效提示 | 9 | 问一部 `status_code=4` 的法 | 回答"该修订版将于 X 日施行；现行有效的是 Y 版" |
| 位阶冲突 | 11 | 法律与司法解释规定不一致时怎么适用？ | 指出位阶关系（法律 > 行政法规 > 司法解释），并说明适用规则 |

- **判分**：答案文本是否包含关键判定要素（"尚未施行" / "现行有效" / 位阶表述），
  由**规则匹配**判定，不用 LLM 打分（可复现）

### F 无答案拒答（n=30，同源等级：弱）

- 三类来源：
  1. 语料外问题（如"帮我起草一份股权代持协议"）
  2. 元数据缺失（266 条 `status_code=None` 里抽——**考"信息不足时是否老实说"**）
  3. 边界问题（"我这个案子能赢吗"——应拒答并说明系统边界）
- **判分**：dev(15) 标定阈值 → test(15) 报告。双侧指标：拒答召回 + 误拒率

## 三、指标定义（统一口径，不得混用）

| 指标 | 定义 | 适用 |
|---|---|---|
| Hit@1 | top-1 是否满足该类判分条件 | 全部 |
| Recall@5 | \|gold ∩ top5\| / \|gold\| | A/B/C/D（**真召回**） |
| Precision@5 | \|gold ∩ top5\| / 5 | **仅当金标集合 > 5 时使用，必须标注为 P@5** |
| 过期法条率 | top-1 所属文档 `status_code != 3` 的题占比 | A/B/C/D |
| 引用准确率 | 答案里的条号能在检索片段中命中的比例 | 生成层 |
| 拒答召回 / 误拒率 | 双侧 | F |

> **旧项目的错误**：同一列"Recall@5"里 A/B/C 用真召回、D 用 `min(5,len)` 作分母（实为 P@5），
> 跨类别不可比却并排展示。本项目**同一张表内指标定义必须一致**。

## 四、实验矩阵（单变量原则）

| 实验 | 变量 | 对照 | 记录 |
|---|---|---|---|
| E0 | — | 纯向量，无融合/重排/时效 | 基线 |
| E1 | 融合方式 | max vs RRF | 五类指标 |
| E2 | 重排 | 开 vs 关 | + 延迟 |
| E3 | 分库硬过滤 | 开 vs 关 | 五类指标 |
| E4 | 时效重排 | 开 vs 关 | **+ 过期法条率** |
| E5 | 嵌入模型 | bge-small(512) vs bge-m3(1024) | 五类指标 |
| E6 | 查询改写 | 关 vs LLM 改写 | B 类为主 |

**每次只动一个变量。** 旧项目的 E2 同时换了评测集和加了重排，导致结论无法归因。

## 六、五层评估指标（**D0 补，吸收自 `PROJECT-1-AGENTIC-RAG.md` §5.2**）

> **为什么要分层**：只报一个"准确率"经不起深究——答错了是**检索没召回**、
> 还是**召回了排太低**、还是**生成引用错了**？分层后每一层都有独立指标，归因才有落点。
> 这五层与 D-15 的链路 trace 是配套的：**指标告诉你掉了多少，trace 告诉你掉在哪一步**。

| 层 | 指标 | 本项目口径 | 目标 | 数据来源 |
|---|---|---|---|---|
| **① 意图路由** | 意图分类准确率 | 五类意图（法条精确 / 口语咨询 / 版本询问 / 跨法条 / 无答案）人工标 100 条 | ≥ 90% | D5 Router |
| **② 检索** | Hit@1 / Recall@5 / MRR | 按 `docs/02` 第三节的统一定义 | Recall@5 ≥ 85% | D4 基线 |
| **③ 评分（Grader）** | Grader 与人工判定一致率 | 抽 100 条，人工标"证据是否充分"作 GT | ≥ 85% | D5 + D-12 附二 |
| **④ 生成** | 引用准确率 / 幻觉率 | 引用准确率 = 条号能在片段命中（D-07）；幻觉率 = 未被片段支撑的论断占比 | 引用准确率 ≥ 90% | D6 |
| **⑤ 端到端** | 任务成功率 / 延迟 / token 成本 / 降级触发率 | 见下"延迟口径修正" | — | D5/D6 |

### 6.1 ⚠️ 延迟口径必须修正（**一代数字不可沿用**）

一代（客服语料、RTX 5070 12GB）写的是 **P99 ≤ 3s**。
本项目**不能用这个数**，两个原因：

1. **硬件变了**：一代跑在 RTX 5070 12GB，该机器已不在（`docs/06`）。当前只有 3070 8GB。
2. **生成层变了**：主模型 `glm-4.5-flash` 实测延迟 **33.8s**（`docs/06` 第四节），
   端到端 P99 不可能在 3s 量级。

**本项目应分两段报延迟**：

| 段 | 口径 | 预期量级 |
|---|---|---|
| 检索段（不含生成） | 向量 ∥ BM25 + 融合 + 重排 | 冷启动 < 15s / 热检索 < 1s（D2 验收项） |
| 生成段 | `glm-4.5-flash` 单次调用 | 约 33.8s（实测） |
| 端到端 | 检索 + 生成 × 迭代次数 | 【待回填】 |

> **口径说明**：不要藏 33.8s，要主动解释取舍——"引用精度是本项目核心指标，
> 1.0s 的 `glm-4-flash` 条号给不全，所以我选了 33.8s 的那个。
> 代价是 210 题评测约 2 小时，可接受。"

### 6.2 五层指标与六类题的对应关系

| 题类 | 主要测哪一层 |
|---|---|
| A 法条精确 | ②检索（**强同源，仅作回归基线**） |
| B 口语化咨询 | ②检索 + ①意图路由（口语→术语的语义鸿沟） |
| C 跨法条关联 | ②检索（多来源同时命中） |
| **D 版本冲突** | ②检索 + **③评分（时效判据）** ← 本项目核心 |
| **E 位阶/未生效** | ③评分 + ④生成（是否指出冲突/未生效） ← 本项目核心 |
| F 无答案拒答 | ③评分 + ⑤端到端（拒答门控） |

## 七、5 类坏例归因（**D0 补，吸收自 `PROJECT-1-AGENTIC-RAG.md` §5.3 并按法律域改造**）

> **用法**：每份 REPORT.md 的失败归因章节按这五类（本项目为六类）打标签。
> **归因比指标重要**——指标只说明掉了多少，归因说明下一步该改什么。

| # | 坏例类型 | 表现 | 本项目特有的触发场景 | 对应修法 |
|---|---|---|---|---|
| 1 | **文档不存在** | 库里根本没有这条法 | 语料只覆盖 2,466 条，冷门部门规章未收录 | 应判为 **F 类拒答**，不是失败 |
| 2 | **分块切碎** | 答案跨块，单块答不全 | 法条按"条"切块，但"第 X 条"含多项（一）（二）（三），切到项级会割裂 | 调切块粒度（D8-4 切块对比） |
| 3 | **语义鸿沟** | 口语问、术语答，向量召不回 | "欠钱不还多久过期" vs "诉讼时效"；"被辞退能拿多少" vs "经济补偿金" | BM25 法律词典（D2）+ 查询改写（D-04） |
| 4 | **意图误判** | 意图分错，走错处理路径 | "2020 年时怎么规定的"被当成普通法条查询 → 返回现行版而非当时版 | D5 Router + D-06 时间锚识别 |
| 5 | **排序错误** | 召回了但排太低被 top-k 截断 | 多版本并存时旧版与新版文本高度相似，旧版挤掉新版 | D-06 时效感知重排 |
| **6** | **版本选择错误**（**本项目特有，一代没有**） | 返回了过期 / 未生效 / 被修订的版本 | 377 个多版本标题下的任意一条 | D-06 时效重排 + **过期法条率**指标 |

> **第 6 类是本项目区别于通用 RAG 的归因维度**：通用 RAG 的坏例只有前 5 类，
> 第 6 类只有在"保留全部历史版本"的设计下才会出现——
> **它是我们自己造出来的难度，也是唯一别人答不出的那一类。**

### 7.1 归因的最小操作流程

1. 从 `eval/results/*.jsonl` 捞出判分失败的题
2. 对每题按上表打**一个主标签**（不允许"多重归因"，否则不可统计）
3. 统计各标签占比 → **占比最高的那一类就是下一轮优化的目标**
4. 挑 3 个 bad case 写**逐字**记录（原查询 / 返回 top-3 / 正确答案 / 归因结论）
5. 优化后重跑，看**该类占比是否下降**（单变量原则，`docs/02` 第四节）
