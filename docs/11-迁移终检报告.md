## 三、本次发现的真 bug：Harness 的"改写回环"是假的

**位置**：`src/agent/harness.py:352-370`

```python
# Rewrite loop: if evaluation fails, augment query and retry
while (not eval_result.get("passed", True)
       and rewrite_count < max_rewrite_attempts
       and "no_observations" not in eval_result.get("issues", [])):
    rewrite_count += 1
    augmented = f"{objective} (补充查询第{rewrite_count}次，请提供更多详情)"
    draft = _generate_draft(augmented, all_observations, errors)      # ← 同一批 observations
    eval_result = _evaluate_result(draft, all_observations, errors)   # ← 同一批，结果必然不变
```

### 三个后果

1. **回环不改变证据**：它只把"生成用的 query 文本"改了，`all_observations` 是**同一批检索结果**。
   证据没变 → 评估结果不会变 → **纯粹浪费一次 LLM 调用**。
2. **"自纠正"名不副实**：真正的 RAG 自纠正是"证据不够 → 改写查询 → **重新检索** → 再评估"。
   现在缺了"重新检索"这一环。**说"我有 rewrite 回环"而实际没有重新检索，这个说法经不起核对。**
3. **`forced_pass: True` 污染评测口径**：回环耗尽时无条件标记通过：
   ```python
   if not eval_result.get("passed", True) and rewrite_count >= max_rewrite_attempts:
       audit.append({"step": "rewrite_exhausted", "forced_pass": True})
   ```
   这会让"评估失败"在审计日志里看起来像通过。

### 对 D5 的影响（必须写进计划）

> **D5 的 Agentic 闭环不能复用这个回环。** 必须新建一条**真正接回检索**的路径：
> `Grader 判定证据不足 → 改写查询 → 重新调用 Retriever → 再判定`，
> 且保留"证据充分性"的**确定性判据**（而不是让 LLM 自评）。

这条已加进 `PLAN.md` D5 的任务描述与 `src/agent/__init__.py` 的模块注释。
