# 01 数据治理与版本策略

> 本文件定义"什么数据能进库、多版本怎么处理、时效怎么判定"。**这是本项目区别于通用 RAG 的地方。**

---

## 一、`status_code` 语义（已实测确证）

flk 官方元数据 `metadata.jsonl` 的 `status_code` 字段，取值与含义：

| code | 含义 | 全库条数 | 占比 | 验证 |
|---|---|---|---|---|
| 3 | **现行有效** | 1,506 | 61.1% | 360 个多版本标题中 353 个（98.1%）的 `status_code=3` 即 `effective_date` 最大者 |
| 2 | **已被修订** | 409 | 16.6% | 同标题下存在更新的 3 或 4 |
| 1 | **已废止** | 275 | 11.2% | 同标题下存在更新的 3 或 4 |
| 4 | **尚未生效** | 9 | 0.4% | **9/9 满足 `effective_date > 今天`（2026-09-28）——100% 一致** |
| None | 未标注 | 266 | 10.8% | 官方未给状态；退回按日期推断 |
| -1 | 未知 | 1 | 0.04% | 单条异常 |

**结论**：`status_code` 可以直接作为"哪一版现行有效"的 ground truth，无需人工标注。

### 1.1 那 7 个"不一致"是什么

360 个多版本标题里，7 个的 `status_code=3` 不是 `effective_date` 最大者。逐条查证：

| 标题 | 各版本 (effective_date, status_code) |
|---|---|
| 中华人民共和国国防动员法 | (2026-10-01, 4), (2010-07-01, 3) |
| 中华人民共和国农业法 | (2027-01-01, 4), (2013-01-01, 3) |
| 中华人民共和国商标法 | (2027-01-01, 4), (2019-11-01, 3), (2014-05-01, 2) |

**这不是错误，是更细的语义**：该标题下存在一个"已公布但尚未施行"的新版（code=4），
所以"现行有效"仍然是旧版（code=3）。

→ **由此推出两类题**：
- **版本冲突题**：应返回 code=3 的版本（不是 code=4 的"最新日期版"）
- **未生效提示题**：应回答"现行有效的是 A 版；B 版将于 X 日施行"

## 二、版本分布（题源盘点）

| 分库 | 原始条目 | 唯一标题 | 多版本标题 | 额外版本条目 |
|---|---|---|---|---|
| 法律 | 734 | 584 | 131 | 150 |
| 行政法规 | 851 | 699 | 126 | 152 |
| 司法解释 | 881 | 752 | 120 | 129 |
| **合计** | **2,466** | **2,035** | **377** | **431** |

> **431 个额外版本条目 = 版本冲突题的题源池。** 旧项目按"同名只保留最新"全部删除（跳过 388 个），
> 等于把本项目唯一的差异化原料当噪音清掉了。

## 三、准入规则

### 3.1 入库

1. 正文 ≥ 100 字（剔除官网的占位/空文件条目）
2. **全部版本入库**，不做"只留最新"的清理
3. front-matter 必填字段：

```yaml
---
source: npc
source_category: 法律 | 行政法规 | 司法解释    # 位阶来源
law_nature: 法律 | 行政法规 | 司法解释
title: <标题>
version: <bbbs>                    # 官网版本号，多版本区分键
status_code: 1 | 2 | 3 | 4 | null  # 时效状态（见第一章）
publish_date: YYYY-MM-DD | null    # 公布日期
effective_date: YYYY-MM-DD | null  # 施行日期
supersedes: <被本版取代的 version> | null   # 同标题内按 effective_date 推导
---
```

### 3.2 不入库

| 类别 | 原因 |
|---|---|
| 正文 < 100 字的条目 | 官网占位文件，无检索价值 |
| 案例库（LeCaRD） | **含真实姓名 PII**（403/500），且金标在库内导致评测失真。待脱敏后单独决策，见 `04-风险与合规.md` |
| 地方法规（28,419 部） | 体量过大、价值密度低；扩容阶段再议 |

## 四、检索期的时效规则

```
查询 → 意图分类
  ├─ 含时间锚（"2020 年时"、"当时"）→ 按 effective_date 过滤到该时点生效的版本
  ├─ 含"现行/现在/最新" → 硬过滤 status_code == 3
  ├─ 含"修订/变化/历史版本" → 返回该标题全部版本，按 effective_date 排序
  └─ 无时间信息（默认）→ 不做硬过滤，但对 status_code==3 加权；
                          status_code==1（已废止）降权；
                          status_code==4（未生效）保留但标注
```

**为什么默认不做硬过滤**：硬过滤会让"跨法条关联题"丢掉已废止但仍在被引用的条文
（旧法被新法取代后，旧案仍适用旧法）。**加权的效果必须实测，不能假设。**

**新增指标：过期法条率** = top-1 所属文档 `status_code != 3` 的题数 / 该类题总数。
这个指标是"时效治理有没有用"的唯一直接证据。

## 五、已知的数据缺陷（必须在文档里如实写）

| 缺陷 | 规模 | 处理 |
|---|---|---|
| `status_code` 缺失 | 266 条（10.8%） | 退回按日期推断；**这 266 条本身可作为"元数据缺失时是否老实说"的题源** |
| `publish_date` 缺失 | 81 条（法律类） | 不影响时效判定（用 effective_date） |
| 位阶关系无显式字段 | 全库 | 从 `source_category` 推导：法律 > 行政法规 > 司法解释（**这是简化，真实位阶还有宪法、地方性法规等**） |
| 官方元数据可能有误 | 未知 | 输出口径为"依据 flk 元数据判定"，不宣称法律意见 |
