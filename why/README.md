# why/ —— 系统是怎么造出来的（工程视角）

这个文件夹讲**工程**：每个关键部分**实际怎么实现的、数据怎么流、代码在哪、为什么必须这么造**。
目标只有一个——**把系统本身讲透**，能对着代码把每个设计推导出来。

## 这个文件夹只讲工程机制与约束

这里只讲**它是怎么造的**：每个设计为什么必须这么造、不这么做下游哪一环会断。
不做"对外该怎么讲"的包装——工程搞懂了，"为什么这么设计"自己能推出来。

## 先读 00

[`00-系统怎么跑起来的.md`](00-系统怎么跑起来的.md) 是全局地图：建库 / 查询 / Agent 三条数据流 + 组件地图。
**看不懂任何一篇时，回 00 找它属于整条链路的哪一环。** 01–14 都是 00 里某一环的放大。

## 每篇的固定结构（工程视角）

1. **它在系统里是什么**：负责哪一环、上游喂给它什么、它产出什么给下游、东西落在哪个文件
2. **数据/接口长什么样**：具体字段、文件名、输入输出的真实示例（不写抽象描述）
3. **代码怎么做的**：关键函数 + 数据流 + 文件路径，你能对着代码读
4. **为什么必须这么造**：工程约束——不这么做，下游哪一环会断
5. **怎么验证它对**：跑哪个脚本、看哪个产物、期望什么数字
6. **代码位置**：去读哪几个文件
